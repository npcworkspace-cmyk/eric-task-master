# 4.2.1 — thinner decisions, stronger target and result checks

## Install or upgrade

Start from [Latest](https://github.com/npcworkspace-cmyk/eric-task-master/releases/latest) and obtain the matching runtime, driving Skill, `SHA256SUMS` and `UNSIGNED-BUILD.txt` from that release. Version 4.2.1 provides native and portable packages for Windows x64, macOS arm64/x64 and Linux x64/arm64. Packages are unsigned; verify their checksums before installation. See [installation and replacement upgrades](../INSTALLERS.md).

Existing installations do not auto-upgrade. Preserve Profile and task state, resolve active work before replacement, and verify the launcher, live Manager and selected Skill versions separately. Release publication and installation are distinct from the source changes described below.

## What changed

Healthy current-command success replies no longer repeat route-known task/operation IDs, ID-only successful action receipts, timings and empty defaults. The selected command/page identity, actual values, explicit warnings, pending/unknown outcomes and positive readback remain available. Full stored receipts are unchanged. Missing verification never implies business success, and missing default Profile identity status never implies a verified website account.

All declared conditions are validated before the first action. Supported URL, DOM state, text and value checks use AND semantics. Actual checked state and complete multi-select collections are verified explicitly. Read, locate and wait actions no longer skip their declared postconditions, and verification metadata records checks actually completed.

Native reference selectors resolve the original connected node, avoiding ordinal-position retargeting after a reorder or replacement while preserving native actionability, typing and dragging. A final dispatch fence checks interruption/control state. Same-document post-fill readback remains available; invalidated references stop explicitly. Wrapped-label names exclude descendant control values, and partial delta contexts reset rather than inventing element removals.

The original pre-acknowledgement page/document/control binding now remains authoritative through native dispatch, including asynchronous authorization and persistence waits. Action groups use one monotonic deadline for explicit waits, checks and the final dispatch fence. A late result is not permission to repeat an uncertain effect, and already committed completion evidence is never rolled back just because its acknowledgement arrived late. Both reference caches refresh observation recency so their bounded retention does not discard controls returned in the current scene.

Connection handoff still reuses the same operation and Profile. A compact or delta reply is not a standalone handoff receipt: retain the operation/task route, latest command/action IDs, progress cursor and unresolved work. A receiving client without the retained scene starts with a fresh observation without the previous baseline ID; reading an old delta with full detail does not reconstruct an uncaptured historical full page.

Every native/portable runtime now includes the [output contract](../OPERATIONS-OUTPUT.md), [persistence guide](../OPERATIONS-PERSISTENCE.md) and [persistent stream contract](../OPERATIONS-STREAM.md) referenced by the Skill; bundle verification rejects missing guides. The bilingual project homepage adds a reusable version-free banner and a clearer Latest-first deployment path.

These changes do not promise universal exactly-once delivery, verified compatibility with every Agent host or website, or elimination of every intermittent native/browser timeout.
