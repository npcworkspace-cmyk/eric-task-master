# 4.2.0 — lightweight operation replies and incremental evidence

This is the source-tree change record. It does not establish that an installer, running Manager or public Latest release has been updated. Publication and installation require separate authorization and matching-version acceptance.

Operations now default to a compact decision view rather than repeating full scene and historical audit records. Fresh references, semantic names, safe values, meaningful states, omissions, selected Profile identity and unresolved-effect information remain available. Full stored receipts and full operation audits are explicit reads, not repeated actions. Text, long names and values support source-bound continuation.

The persistent CLI stream reuses one client process. Hot authorization/action records use a synchronized incremental journal; completed bulky replies use verified immutable evidence files. Legacy migration preserves complete logical replies. Pending/unknown effects and replay protection remain active, and missing or corrupt evidence fails closed. Snapshot, journal and evidence directory must be backed up together; do not run an older runtime against migrated state.

Known local preparation can coalesce its result acknowledgements without removing live authorization, page identity or external-effect durability checks. Failure-only bounded stage diagnostics distinguish authority, persistence, target resolution, browser action, verification and observation without recording page text or input values. No forced click, page freeze, automatic effect replay, permission cache, additional model or speculative Chrome flag is introduced.

Smaller JSON is not a measurement of model tokens or inference cost. Source tests and a synthetic local benchmark do not prove every real website, physical device or unattended host state.
