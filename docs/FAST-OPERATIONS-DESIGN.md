## Product boundary and minimal architecture

The main Agent alone makes semantic decisions. No second Agent/model, no MCP, Task Type registry, Task Pack framework, platform selector database or dependency addition. Keep ordinary script CLI and lifecycle behavior unchanged. A persistent session is one existing Manager task/worker/browser, not a new process per command. Reuse task stop/resume, Profile lease, process cleanup, output limits and authenticated loopback transport. A small operations service owns durable authorization, records, scheduler and event outbox; the worker owns page observation, condition waits and bounded actions.

Minimal explicit AGENTS amendment: owned Profiles remain the ordinary script default; new account-backend sessions default to `local-browser`, and must not fall back to owned Profiles. A Profile requires explicit per-task selection. `local-browser` means the documented host browser-use capability, not arbitrary CDP attachment or copied credentials. If no usable host adapter is present, return `BROWSER_ADAPTER_UNAVAILABLE` with the two choices required by local-browser-admin. Preserve the selected live browser; do not launch a substitute, modify debug settings or close its process. An isolated test Profile is permitted only in the local test suite. Add the new bounded operations service as a narrowly justified exception to scripts owning all browser behavior; Dashboard stays Tasks/Profiles.

Host capability is explicit: `active-wait` can consume a long-poll event and submit the main Agent's decision through CLI; `session-ended` and `app-closed` require a real installed host dispatch adapter. Implement an executable, argument-array (no shell interpolation), bounded stdin/stdout JSON adapter that the operator explicitly configures. Its receipt must identify accepted delivery; process launch or notification is not receipt or decision. No bundled claim that closed Codex can be awakened. Without adapter, retain events as pending and report `adapter-required`; test a real local adapter process as plumbing, not as proof of native Codex wake-up.

Final user clarification: modes are explicitly in scope, superseding the old AGENTS prohibition. There are exactly two execution modes: `batch` (finite script/action sequence then finish) and `operations` (persistent command/event waiting). "Manual selection" means the user explicitly chooses one of those two modes in the current prompt; it is not a third execution mode. `auto` is a Profile selection policy, not an execution mode. Persist Profile `modePolicy: batch|operations|auto` (migration default `auto`) and expose selection plus actual mode/reason on existing Profile/Task UI. Precedence: current prompt's explicit mode > saved Profile default; only when the saved policy is auto and no explicit mode is supplied, use declared Skill recommendation/task intent, then the finite-script compatibility default batch. A prompt override applies only to the current task and never rewrites the saved Profile policy. Skill intent is supplied through task input, not inferred from page text. Auto can select operations for waiting/follow-up intent, but transitions happen only between commands, with prior write reconciled and records retained; mode change never changes account/Profile or expands authorization. Human takeover remains an independent pause/ownership lock, not a mode: it cancels pending automation, invalidates observations and preserves the browser; continuing automation requires explicit release/resume and fresh observation, regardless of mode selection. Repo Skill documents selection/examples; installed Skill remains untouched. Add tests for persistence, migration default, precedence, per-task prompt override without Profile mutation, takeover and safe transitions; do not reject an explicit mode merely because it differs from the saved Profile default.

## Interface freeze

Add `taskmaster ops <verb>` rather than change existing commands. JSON input uses existing CLI file/JSON conventions. Required verbs: `start`, `get`, `command`, `events`, `ack`, `decide`, `pause`, `resume`, `takeover`, `revoke`, `stop`, `stop-all`, `reconcile`. `events --wait-ms` is a bounded long poll with cursor, not busy Agent polling. Schedule and host adapter configuration are part of start/update input; expose `update` if needed. `stop-all` affects operations sessions only and reports scope.

Manager uses authenticated `/v1/operations` and `/v1/operations/:id/{commands,events,actions}` routes. No new unauthenticated listener. `start` returns operation ID and existing task ID. `command` durably reserves a unique command ID then submits it to the same worker; returns its result or a pending receipt, never a fabricated success. `events` permits later retrieval. Same command ID + different payload is conflict. Simultaneous mutating commands are rejected/serialized before browser access. The service must revalidate current authorization before dispatch, not trust command-supplied permission.

B exports `runFastSession(runtime)` from `fast-session.mjs`; A imports it from the existing task-worker's explicit built-in execution branch. Do not copy a module with broken relative imports into the disposable script directory. A may add an explicit built-in task kind while preserving ordinary `modulePath` validation. Runtime passed to B: existing `page`, `context`, `input`, `signal`, `outputDir`, `emit`, `wait`, plus `durable(type,payload)` returning a Manager persistence acknowledgement. Worker `durable` uses correlated IPC requests; A persists and acknowledges before B continues. Existing best-effort `emit` is NOT a sufficient pre-submit journal.

Session loop receives each command through existing `wait`/`resume`, runs it, emits compact result, and waits again without browser relaunch. `wait.reason = operations-command` has no verification reminder loop. Main Agent continuation and timers resume the same task only while its wait ID matches. Startup/restart creates a reconcile-required session rather than replaying writes. Keep decision wait distinct from page-local wait; no model call during the latter.

Command envelope: `{schemaVersion:1, commandId, operationId, authorizationVersion, pageId, pageVersion, kind, payload}`. Kinds: `observe`, `batch`, `wait`, `screenshot`, `tabs`, `select-tab`, `reconcile`. Reply: `{commandId,status,pageId,pageVersion,result,evidenceRef,needsDecision,reason}`. `status` is `confirmed|stopped|failed|unknown|pending`. Errors have stable codes. Bounds on bytes, actions, timeout, observations and retained evidence are validated before execution.

Batch: `{preconditions,stopConditions,actions:[{actionId,type,target,value,expected}],verify}`. Supported primitives: locate/read, click, fill, select, scroll, key, selected-tab navigation; no arbitrary code string from page data. All target matches must be unique and actionable. Page identity + revision invalidate stale references; re-observe after navigation, takeover or unknown dialog. Explicit expected navigation is permitted. Before each effect, recheck cancellation, active authorization version, scope, identity, page conditions and target. After an unexpected navigation/dialog/account change, stop remaining actions. A write lacking a positive result verification becomes `unknown`.

## Durable schemas and invariants

Use versioned atomic JSON storage under the isolated Manager state directory with serialized mutation, bounded record counts/bytes, retention and private-file safeguards. Reuse existing JSON and redaction utilities. Full action evidence may be bounded artifacts, never credentials/cookies/OTP. Redaction is before persistence, not merely when printing. Do not truncate the safety envelope, pending decision or required context; return a separate compact `context-insufficient` result if the requested output budget cannot preserve it.

* Operation: `{id,taskId,goal,businessKind,browserSelection,authorization,currentStep,completedActionIds,pending,nextTrigger,decisionSummary,status,budgets,counters,createdAt,updatedAt}`.
* Authorization: `{id,version,grantedAt,expiresAt,revokedAt,accountId,resourceIds,origins,allowedActions,limits,stopConditions}`. Limits include frequency/daily count/cooldown; advertisements additionally fields, currency, budget type, per-change/cumulative bounds; site destructive fields require explicit permission. Page content cannot change authorization. Actor identity and currency are required evidence, not caller assertions alone.
* Action: `{actionId,commandId,operationId,authorizationVersion,accountId,resourceId,businessKey,kind,before,proposed,reason,status,startedAt,confirmedAt,verification,evidenceRef}`. State machine `prepared -> initiated -> confirmed|unknown|failed`; persist `initiated` ACK before external effect. Lost completion ACK means unknown; never automatically retry an initiated/unknown effect. Reconcile reads actual resource and records confirmed/failed/still-unknown; manual changes are conflicts, not permission to overwrite. Claim no exactly-once guarantee.
* Business record: social `{platform,communityId,postId,conversationId,readThrough,replyId,replyResult,followUp,cooldownUntil}`; ads `{platform,accountId,campaignId,before,after,currency,budgetType,dataRange,dataAsOf,attribution,observationUntil,performance}`; site `{accountId,domain,resourceId,before,after,submissionStatus,readback,propagation,effective,rollback}`.
* Event: `{id,dedupeKey,operationId,type,priority,createdAt,expiresAt,payloadRef,summary,state,deliveryId,attempts,deliveredAt,receivedAt,handledAt}`. Durable transitions `pending -> delivered -> received -> handled`; failed delivery retries with bounded backoff and same ID, never duplicate action. Receipt alone never marks handled. Explicit decision tied to event ID/auth version returns next bounded command or keep-waiting/stop. Expired/revoked events cannot dispatch actions. Pending safety events survive coalescing and retention.
* Schedule: `{timezone,nextAt,intervalMs,allowedWindow,maxRunsPerWindow,misfire:'once'|'skip',expiresAt}`. Validate IANA timezone and positive finite intervals. Timezone-aware allowed hours including overnight, one coalesced overdue trigger after resume, no backlog burst. Expose observed scheduler drift. UTC timestamps stored; local window evaluation uses specified timezone.
* Budgets: runs, wall duration, host calls, and nullable actual input/output token/cost limits. Unknown usage is `unobservable`, never character estimates. Do not claim enforcement of unavailable spend; enforce observable limits and pause when configured token/cost enforcement lacks needed measurements.

## Browser observation, local waiting, workflow closure

Observe supports scope/selector, field selection, max characters/items, continuation and delta baseline ID. Return omitted ranges and `baselineReset` when a baseline is invalid. No default full DOM/screenshot. Ignore explicitly configured volatile fields only; errors, identity/permissions and deadlines are never suppressed. Read-only concurrency is bounded across independent scopes/pages; linked reads, writes and verification remain sequential. Optional region screenshots give explicit artifact references and private-data masking/omission boundaries. Unsupported structure becomes `needsDecision` with visual option, not guessed success.

Wait supports actionable target, text/state, save result, download, timeout and cancellation. Watchers recover on navigation/refresh/reconnect and have a health signal; lost watcher, login expiration, no progress, deadline and disconnection each produce a distinct durable event. Avoid unlimited polling or unbounded listener growth.

B provides three runnable isolated workflows using the SAME session commands and ledger, not separate fake shortcut implementations: social discover/read/rules -> main-Agent decision event -> reply -> verify -> follow-up delta; Google/Meta-labelled simulated ad inspect -> data sufficiency/limits -> decision -> change -> readback -> observe; website simulated locate -> identity/resource -> before -> decision -> save -> readback -> propagation/effective states/rollback evidence. Main-Agent text/strategy is supplied through `decide`; no deterministic template pretends to make a semantic decision. Fixtures exercise changed page entry paths, ambiguous targets, dialogs, insufficient ad data, permission changes and write-result uncertainty. Real platform compatibility stays unverified.

### Root decision bridge (same contract for both lanes)

The supervisor only injects, detects, snapshots, measures and verifies. It cannot generate a semantic decision, feed itself an approved response or count an oracle answer as root intervention. The root Agent observes current compact CLI events/get plus permitted page evidence, selects existing CLI commands, and explicitly ack/decides or refuses. Recovery must retain operation/task/browser IDs unless the declared restart scenario makes that impossible; record old/new IDs rather than calling it same-session continuity.

Output per lane: `run-manifest.json`, `status.json`, append-only `challenges.jsonl`, `requests/<challengeId>.json`, root-created `decisions/<challengeId>.json`, `resource-samples.jsonl`, and final `report.json`. Unique challengeId is `${runId}:${lane}:${sequence}`. Request schema: `{schemaVersion:1,challengeId,runId,lane,seed,sequence,scenarioId,operationId,taskId,eventIds,injectedAt,detectedAt,observationRef,pendingDecision,deadlineAt}`. The private test oracle stores the expected safety boundary separately; request evidence describes the observed page, not the desired answer.

Root decision record: `{schemaVersion:1,challengeId,actor:'root-main-agent',observedAt,decisionAt,summary,disposition:'execute'|'refuse'|'defer'|'stop',commandIds,eventIds,evidenceRefs}`. Root performs actual CLI commands; the driver reads their actual persisted results, task state and independent fixture state before verifying. A decision JSON alone is not success. A wrong challenge ID, stale page observation, missing root record or no matching persisted command/receipt must not be credited. Refusal may use an ack/decide record with no mutation; oracle must confirm zero prohibited effect. The only valid automatic recovery is a predeclared deterministic mechanical action, labelled `mechanical`, separately from main-Agent-handled cases; it does not fulfill live root-decision coverage.

At least one genuine root decision per scenario family in each lane is required; do not satisfy this with all-script cases. All unresolved requests stay visible to root. Root consumes both lanes in the current chat, responds on changes, and retains pending state across context transitions; closed-Codex wake-up is not claimed. No timeout chooses an answer. Operators may create `STOP` in a lane output for bounded cleanup, or `HOLD` to suppress further injection while retaining monitoring and pending evidence. Hold/Agent absence is recorded as coverage/latency, not silently excluded from elapsed time.

### Metrics, continuity and outcome

Record UTC timestamps plus monotonic elapsed times: injectedAt, detectedAt, agentStartedAt/observedAt, decisionSubmittedAt, firstRecoveryActionAt, verifiedAt, resumedAt. Derive detection, Agent queue, handling and end-to-end recovery latency separately. Keep missing values null, count timeouts/failures in denominators, never compute speed only from successes. Report medians/tails and worst cases per lane; no hard universal speed promise is established by this test.

Each challenge outcome is `resolved`, `correctly_refused`, `unresolved`, or `failed`, with evidence and `sameSessionRecovered` boolean. Correct refusal is a safety success but not a solved-popup success; show separate counts/rates. An unknown write requires same-resource readback and zero extra submission. Source/runtime hashes and seed are in manifest. Sample resource/process/page/listener/queue state at least every minute; keep actual sample gaps. Unexpected supervision gap over 120 seconds marks continuity invalid; clock jumps and sleep must not become extra valid hours.

Deliberate restart is valid fault coverage but creates a new continuity segment; the report distinguishes the four-hour supervised experiment from uninterrupted single browser session. Harness restart does not pretend to continue a previous monotonic clock: start a new segment, preserve manifest and report supervised covered duration and gaps. Product fixes during the run get new source hashes and a new evidence segment; root decides whether the changed capability needs a fresh four-hour run. Fixture parameter changes alone remain planned injections with recorded seed/override history. Finish requires both lanes' real duration, declared family coverage, genuine root-decision coverage, no unauthorized/duplicate effects, truthful failed/unresolved outcomes and clean scoped shutdown.
